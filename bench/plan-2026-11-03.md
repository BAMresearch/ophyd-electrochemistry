# Bench plan 2026-11-03 (unscheduled session) — B0, output OFF only

Purpose: answer the firmware questions that decide the sequencer runtime (O5)
design. **The source output is never turned on**, so this is below tier 1: no
load is energized. Expected time: 10 minutes including setup.

## Confirm once before running

- [ ] K2460 serial `04686198` on `169.254.113.151:5025`, TSP mode, Ethernet link up
- [ ] Output OFF on the front panel; **no cell connected** (resistor or nothing)
- [ ] Nobody else is connected to the instrument (one owner)
- [ ] Note: the probe leaves the output-off mode at **HIGH-Z** (was NORMAL) and
      the trigger model EMPTY. The installed v17 runtime, its retained reading,
      and `defbuffer1` (12,867 records) are not touched or cleared.

## Steps (from the repository root, laptop on the instrument link)

1. Query-only connection check (sends no configuration or output command):

   ```sh
   uv run --locked --extra visa ophyd-electrochemistry-k2460-diagnose \
     --resource 'TCPIP0::169.254.113.151::5025::SOCKET' --backend '@py' --require-language TSP
   ```

   Expect identity with serial 04686198, TSP, output OFF. Stop if not.

2. Feature probe (about 1 minute):

   ```sh
   uv run --locked --extra visa python bench/feature_probe.py --i-confirm-output-off
   ```

   It stops by itself if the serial differs, the output is not OFF or a trigger
   model is running. Each probe runs under Lua `pcall`; an unsupported command
   is recorded as `ERR ...`, which is a valid answer, not a failure.

3. Check the front panel: output OFF, no error indicator. The probe writes
   `docs/evidence/k2460-2026-11-03-feature-probe.json`. Leave it uncommitted;
   Claude reviews it and records the result in `docs/validation.md`.

## What each answer decides

| Probe | Question | Design consequence |
|---|---|---|
| P1 | Current off mode, function, error count | Baseline |
| P2 | HIGH-Z off mode settable | Required for cells; if not, stop and rethink |
| P3 | One source config list holds current and voltage entries | CC and CV steps in one list |
| P4A/B | Does `BRANCH_ON_EVENT` latch timer events? | Explains v17; whether timer branches are usable |
| P5 | Largest reading buffer (1M / 500k / 250k) | Records per run before chunked offload is needed |
| P6 | Buffer readable in chunks while the model measures | Live plotting from the instrument buffer (O4 design) |
| P7 | Config recall switches source *and* measure function in one model | CC→CV steps with V and I both recorded |

Not in this session (need output ON, tier 1 on the resistor, and the
sequencer runtime): function switch with output on, step-marker TTL, HIGH-Z
behaviour at output-off, cutoff branches.

## If something goes wrong

Ctrl-C is safe: the output is never on. If the script stops mid-probe, run
step 1 again and report the output; do not rerun the probe until Claude has
looked at the state (a temporary buffer `oe_live`/`oe_switch` or config lists
`OE_SRC`/`OE_MEAS` may remain; they are harmless and deleted on the next run).
